# heripo engine 로드맵

[English](./roadmap.md) | **한국어**

## 비전

고고학 발굴조사보고서 PDF에서 구조화된 데이터를 추출하고, 표준 형식으로 정규화한 후 데이터베이스에 저장하여 체계적인 분석과 활용을 가능하게 합니다.

## 데이터 파이프라인

```
원천 데이터 추출 → 고고학 데이터 원장 → 고고학 데이터 표준 → 분야별 온톨로지 → DB 저장
```

각 단계:

1. **원천 데이터 추출**: PDF 보고서의 양식 그대로 구조적으로 추출한 **문서 데이터**
   - DoclingDocument: PDF에서 추출한 텍스트, 표, 이미지 정보
   - ProcessedDocument: 목차/챕터/페이지 구조로 정제된 문서
   - 고고학적 해석 없이 문서 구조만 추출
2. **고고학 데이터 원장**: 전세계 고고학을 포괄하는 범용 모델로 구조화된 원장
   - 지역/시대/분야를 가리지 않는 범용 고고학 개념 모델
   - 문서 데이터에서 고고학적 개념(유구, 유물, 층위 등)으로 변환
   - 표준화 전 단계이지만 정규화를 전제로 설계
3. **고고학 데이터 표준**: 확장 가능한 표준 모델로 정규화된 데이터
   - 기본 표준: 한국고고학 표준 등 국가/지역별 기본 표준
   - 확장 표준: 신라 고분 표준, 백제 토기 표준 등 세부 분야별 확장
   - 필요에 따라 다양한 하위 표준 생성 가능
4. **분야별 온톨로지**: 도메인 특화 시맨틱 모델
   - 온톨로지 기반 의미론적 검색
   - 지식 그래프 구축
5. **DB 저장**: 각 파이프라인 단계별로 독립적 저장 및 활용 가능
   - 단계별 데이터는 별도로 관리되며 각각의 활용 목적을 가짐

## 현재 상태 (v0.2.x)

원천 데이터 추출 단계(v0.1.x)는 완료되었습니다. 0.2.x 릴리스는 새로 배포되는 패키지 `@heripo/ledger-extractor`로 고고학 데이터 원장 단계의 첫 구현을 추가합니다. 원장 형식 `archaeology-ledger.v1`은 실험적입니다.

### ℹ️ 참고 사항

| 항목               | 설명                                                                                                        | 상태         |
| ------------------ | ----------------------------------------------------------------------------------------------------------- | ------------ |
| **OCR 보정**       | OCR은 ocrmac으로 고정되며, Docling 변환 후 언어와 관계없이 모든 페이지에 VLM 텍스트/표 셀 보정을 적용       | ✅ 해결됨    |
| **목차 의존성**    | 목차 없는 보고서는 처리 실패 (의도된 동작). 드문 추출 실패는 human intervention으로 대응 예정               | 📋 설계 의도 |
| **세로쓰기 문서**  | 페이지 번호가 한자인 오래된 세로쓰기 문서 (장기 목표, 현재 계획 없음)                                       | 📅 장기 목표 |
| **원장 검증 범위** | 원장 단계는 보고서 세 권(태안 마도, 부여 화지산, 거제 사등성)으로만 개발·측정됨                             | ⚠️ 제한적    |
| **원장 형식**      | `archaeology-ledger.v1`은 실험적이며, 필드·검수 항목·프롬프트가 0.2.x 안에서 마이그레이션 없이 바뀔 수 있음 | 🧪 실험적    |

### ✅ 구현 완료

#### v0.1.x - 원천 데이터 추출

**PDF 파싱 및 OCR**

- Docling SDK를 활용한 PDF 파싱
- ocrmac(Apple Vision Framework)으로 고정된 Apple Silicon OCR
- 고품질 한국어 문서 인식
- 필수 VLM 보정 — ocrmac은 대량 처리에 탁월하며(무료, GPU 가속, 고품질), 이후 텍스트나 표가 있는 모든 페이지에 VLM 텍스트/표 셀 보정(한자 복원, 문자 체계 인식 보정)을 적용; 페이지 게이트를 거치는 구조 검토와 표 보정은 선택 사항
- 이미지 자동 추출

**문서 구조 추출**

- 규칙 기반 + LLM 폴백 목차 추출
  - TocFinder: 키워드 및 구조 분석
  - VisionTocExtractor: Vision LLM 폴백
  - TocExtractor: 계층적 구조 추출
- 페이지 범위 매핑 (Vision LLM)
- 챕터 계층 구조 생성

**리소스 처리**

- 이미지 추출 및 캡션 파싱
- 테이블 추출 및 캡션 파싱
- LLM 기반 검증 (TocContentValidator, CaptionValidator)

**LLM 통합**

- Vercel AI SDK 통합
- 다중 LLM 프로바이더 지원 (OpenAI, Anthropic, Google, Together AI, Ollama, LM Studio)
- Fallback 재시도 메커니즘
- 토큰 사용량 추적

#### v0.2.x - 고고학 데이터 원장 (첫 구현, `@heripo/ledger-extractor`)

**입력 및 원문 조회**

- `ProcessedDocument` 런타임 검증과 제한된 추출 미리보기
- LLM 호출 없는 문서 전체 리소스 색인 (챕터, 텍스트 블록, 이미지, 표, 그리드 셀, 각주)

**보고서 프로필**

- 결정론적 보고서 신호 + 보고서 특성을 판정하고 조사 범위를 제안하는 LLM 라우터 호출 1회
- 제안된 범위를 코드로 보완; 사람이 프로필과 범위를 JSON으로 직접 주입할 수도 있음

**조사 객체 등록부**

- 챕터 단위별 후보 탐색 (유적, 구역, 트렌치, 층위, 유구, 유물, 난파선, 미상) — 원문 인용을 그대로 보존
- 중복 검토: 코드가 판정할 수 있는 병합을 먼저 처리한 뒤 나머지 후보를 LLM이 검토; 불확실한 동일성은 검수 항목으로 남김
- 동결된 후보 등록부: 모든 원장 레코드는 등록부 항목 하나에서 생성

**내용 배정 및 관계**

- 단위별 얇은 내용 배정: 단위마다 2회 실행, 두 실행이 함께 반환한 대상은 자동 확정, 실행끼리 갈린 곳은 동점 해소 실행으로 세 실행 중 둘이 같은 쪽을 확정하고 나머지는 검수로 보냄. 구역 대상은 보고서 프로필이 있으면 두 실행이 일치할 때 확정하고, 프로필이 없으면 항상 검수로 보냄
- 상위 계층: 출토 위치 표현과 표 행으로 코드가 정하는 상위 레코드, 남은 질문에 대한 LLM 3회 판단(모든 실행이 일치할 때만 확정), 사람이 주입하거나 LLM 2회 제안으로 얻는 장소 약칭 표
- 도면·사진 참조, 표·본문 속성, 규칙 기반 레코드 링크, 관계 후보로 보존하는 층위 언급

**원장 조립 및 검증**

- `archaeology-ledger.v1`: 레코드, 출처, 속성, 미디어 참조, 링크, 검수 항목, 이슈를 저장된 모델 결과로부터 결정론적으로 조립
- 원본 문서 대비 원장 검증 (구조, 계층, 원문 범위, 값 충실성)
- 모든 레코드는 원문 텍스트와 출처 참조를 보존; 모델 출력은 검사하되 절대 고치지 않으며, 해결되지 않은 판단은 사람이 결정할 검수 항목이 됨
- 호출 수와 토큰에 절대 상한을 거는 지출 가드 (`createSpendGuard`, `@heripo/shared`에서 제공)

**데모**

- 데모 웹 앱이 단계별 모델(기본 Claude Haiku 5.5, LM Studio를 통한 로컬 모델도 가능)로 원장 파이프라인 전체를 실행하고 결과 원장을 표시
- 여러 전처리 문서를 보고서별·배치별 상한 안에서 처리하는 CLI 배치 실행기 (`pnpm --filter @heripo/demo-web ledger:batch`), Anthropic 모델은 기본적으로 Anthropic Message Batches API 사용
- 보고서 1건(태안 마도, Claude Haiku 5.5) 실측: 실행당 약 0.33달러(US$), 검수 항목 약 15개

## 계획된 기능

### v0.2.x - 데이터 원장

**목표**: 전세계 고고학을 포괄하는 범용 모델로 구조화된 원장 생성

**상태**: 🚧 진행 중 — 0.2.x에서 첫 구현 배포 (`@heripo/ledger-extractor`, 실험적 `archaeology-ledger.v1`)

**설계 철학:**

- **범용성**: 지역/시대/분야를 가리지 않고 전세계 고고학 데이터를 수용할 수 있는 모델
- **원문 충실성**: 원장 내용은 원천 문서를 고치지 않고 인용하며, 모델 출력은 검사만 하고 고치지 않음
- **정규화 전제**: 표준화를 위한 기반 데이터로서, 정규화가 가능한 구조로 설계

**주요 작업:**

1. **범용 스키마 설계** — 🚧 일부 완료
   - ✅ 실험적 `archaeology-ledger.v1`: 여덟 종류(유적, 구역, 트렌치, 층위, 유구, 유물, 난파선, 미상)의 레코드와 출처, 속성, 미디어 참조, 링크, 검수 항목
   - ✅ 열린 특성 목록을 가진 보고서 프로필 (새 보고서 유형은 `x-` 접두 특성으로 기록)
   - 📋 범용 스키마 확정 및 0.2.x 릴리스 간 안정적인 형식

2. **고고학 개념 추출 파이프라인** — ✅ 첫 구현
   - ✅ 유구, 유물, 층위, 구역, 트렌치를 출처가 붙은 후보로 추출하고 중복 검토
   - ✅ 상위 계층 (코드 결정, LLM 판단, 주입 가능한 장소 약칭)
   - 📋 개발에 쓴 보고서 세 권 외의 보고서와 보고서 유형에서 검증

3. **테이블 파싱 강화** — 🚧 일부 완료
   - ✅ 레코드가 소유한 행과 키–값 표에서 속성 추출 (논리 그리드, 병합 헤더)
   - ✅ 관계 열을 레코드 링크로 변환
   - 📋 더 다양한 보고서 양식 대응

4. **LLM 기반 정보 추출** — 🚧 일부 완료
   - ✅ 본문과 표에서 고고학 객체 탐색 및 내용 배정
   - ✅ 캡션과 본문에서 도면·사진 참조
   - ✅ 규칙 기반 레코드 링크(중복, 파괴, 인접, 거리)와 관계 후보로서의 층위 언급
   - 📋 더 완전한 관계 추출 (층위 언급에서의 관계 포함)

5. **데이터 모델 구현** — 🚧 일부 완료
   - ✅ `ArchaeologyLedgerResult` (`archaeology-ledger.v1`)와 확장 가능한 레코드 종류
   - ✅ 원장 검증과 검수 항목
   - 📋 검수 항목을 처리하는 사람용 검수 UI (현재 데모는 검수 표시만 제공)

**현재 출력 (실험적 `archaeology-ledger.v1`, 0.2.x 안에서 변경될 수 있음):**

```typescript
// 단순화한 형태입니다. 전체 타입은 @heripo/ledger-extractor를 참고하세요
interface ArchaeologyLedgerResult {
  ledger: ArchaeologyLedger; // 헤더: 버전, 프로필, 검증/검수 상태
  records: LedgerRecord[]; // 원문 내용 발췌를 가진 조사 객체
  sources: LedgerRecordSource[]; // 각 발췌의 위치 (페이지, 챕터, 범위, sourceRef)
  attributes: LedgerRecordAttribute[]; // 표와 본문의 값을 적힌 그대로 보존
  mediaReferences: LedgerMediaReference[]; // 레코드에 연결된 도면과 사진
  mediaCandidates: LedgerMediaCandidate[];
  layerMentions: LedgerLayerMention[]; // 관계 후보
  links: LedgerRecordLink[]; // 레코드 간 관계
  pending: ArchaeologyLedgerPendingPart[];
  reviewItems: LedgerReviewItem[]; // 사람에게 맡긴 판단
  issues: LedgerExtractionIssue[];
}
```

### v0.3.x - 표준화

**목표**: 확장 가능한 표준 모델로 원장 데이터를 정규화

**첫 단계**: 원장 데이터에서 표준 모델 추출 (0.3.0부터 시작)

**설계 철학:**

표준 데이터는 **계층적 확장 모델**로 설계됩니다:

```
기본 표준 (Base Standard)
└── 국가/지역별 표준 (Regional Standard)
    └── 분야별 확장 표준 (Domain Extension)
```

**표준 계층 예시:**

| 계층        | 예시                                                              |
| ----------- | ----------------------------------------------------------------- |
| 기본 표준   | 범용 고고학 표준                                                  |
| 국가별 표준 | 한국고고학 표준, 일본고고학 표준, 영국고고학 표준 등              |
| 분야별 확장 | 신라 고분 표준, 백제 토기 표준, 마한 분묘 표준, 가야 철기 표준 등 |

**주요 작업:**

1. **확장 가능한 표준 포맷 설계**
   - 기본 표준: 전세계 공통 고고학 용어 및 분류 체계
   - 국가/지역별 표준: 해당 지역 고고학 용어집 기반 확장
   - 분야별 확장 표준: 특정 시대/유적/유물 유형에 특화된 표준
   - _세부 표준 스키마는 추후 확정_

2. **정규화 파이프라인**
   - 원장 데이터 → 기본 표준 변환
   - 기본 표준 → 국가/지역별 표준 확장
   - 필요시 분야별 확장 표준 적용
   - 단위 표준화, 시대 분류 표준화

3. **데이터 검증**
   - 각 표준 계층별 필수 필드 검증
   - 데이터 형식 검증
   - 참조 무결성 검증

4. **매핑 규칙**
   - 원장 용어 → 표준 용어 매핑
   - LLM 기반 애매한 케이스 처리
   - 커뮤니티 기여를 통한 매핑 규칙 확장

**예상 출력 (참고용 예시, 세부 구조는 미확정):**

```typescript
// 아래는 개념적 예시이며, 실제 구현 시 변경될 수 있습니다
interface StandardArchaeologyData {
  reportId: string;
  baseStandard: string; // 적용된 기본 표준
  regionalStandard?: string; // 적용된 지역 표준
  domainExtensions?: string[]; // 적용된 분야별 확장 표준
  standardFeatures: StandardFeature[];
  standardArtifacts: StandardArtifact[];
  standardStrata: StandardStratum[];
  validationResults: ValidationResult[];
  // 세부 필드는 추후 확정
}
```

### 커뮤니티 기여 환영

heripo engine은 전세계 고고학 커뮤니티의 다양한 기여를 환영합니다. 국가, 지역, 문화권을 가리지 않고 누구나 참여할 수 있습니다.

#### 🌍 지역별 표준 기여

전세계 각 지역의 고고학 표준을 함께 만들어갑니다:

- **동아시아**: 한국, 일본, 중국, 대만, 몽골
- **동남아시아**: 베트남, 태국, 캄보디아, 인도네시아, 필리핀
- **남아시아**: 인도, 파키스탄, 스리랑카, 네팔
- **중앙아시아**: 우즈베키스탄, 카자흐스탄, 키르기스스탄
- **중동 및 서아시아**: 이란, 이라크, 터키, 이스라엘, 요르단, 이집트
- **유럽**: 영국, 프랑스, 독일, 이탈리아, 스페인, 그리스, 북유럽
- **아프리카**: 이집트, 에티오피아, 남아프리카공화국, 케냐
- **아메리카**: 미국, 멕시코, 페루, 브라질, 아르헨티나
- **오세아니아**: 호주, 뉴질랜드, 폴리네시아

#### 🏛️ 분야별 온톨로지 기여

다양한 시대와 분야의 온톨로지를 함께 구축합니다:

- **시대별**: 선사시대, 청동기, 철기, 고대, 중세, 근대
- **유적 유형별**: 주거지, 분묘, 생산유적, 관방유적, 종교유적
- **유물 유형별**: 토기, 석기, 금속기, 목기, 유리, 직물
- **특수 분야**: 수중고고학, 산업고고학, 도시고고학, 환경고고학

#### 🌐 다국어 지원 기여

다양한 언어로 시스템을 확장합니다:

- 한국어, 영어, 중국어(간체/번체), 일본어
- 아랍어, 페르시아어, 히브리어
- 스페인어, 포르투갈어, 프랑스어, 독일어, 이탈리아어
- 힌디어, 타밀어, 벵골어
- 러시아어, 폴란드어, 체코어

#### 🔧 기술 기여

- 새로운 LLM 프로바이더 통합
- PDF 외 추가 문서 형식 지원 (DOCX, HTML, XML 등)
- Linux/Windows 플랫폼 지원
- 분야별 특화 프로세서 개발
- 성능 최적화 및 버그 수정
- 문서화 및 번역
